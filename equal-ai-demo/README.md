# 生成AI伴走支援 導入デモ ― 株式会社イコール様向け

`index.html` / `dashboard.html` を開くだけで動く単体デモです（ビルド・サーバー不要）。商談の場でブラウザで開いて操作しながら説明する想定です。2ページは上部のナビで行き来できます。

## 使い方

### index.html — AI受注登録アシスタント（1件ずつの処理を見せる）

1. `index.html` をブラウザで開く
2. 「AI受注登録アシスタントを試す」セクションで3つのケースを切り替えながら「AIで解析する」を押す
   - ケース1: 整型フォーマットの発注、見積と一致 → フル自動で受注登録まで完了
   - ケース2: 数量変更の発注連絡 → 見積との差分を検知し登録を保留、金額・納期の再計算確認文を自動生成（RPAが苦手とする部分）
   - ケース3: 品番が特定できない発注 → 社内マスタと突合できず候補提示までにとどめ、最終確認は人が行う（過度な自動化を謳わない、誠実な線引き）
3. 解析結果に含まれる金額・時間は説明用のサンプル値です（画面内にも明記済み）

### dashboard.html — 受発注自動化 運用ダッシュボード（導入後の日常運用を見せる）

- 本日のサマリー（受注件数・自動登録率・要確認件数・削減時間の目安）
- 自動登録率の推移（伴走支援で精度が上がっていくイメージ。グラフにカーソルを合わせると週ごとの値が出ます）
- 本日の受注一覧（自動登録済み／要確認／保留中のステータスが一目でわかる一覧）
- 要確認・保留の内訳（数量相違・品番不一致など、何が引っかかっているかの内訳）

`index.html` の1件ずつの挙動を見せたあと、「これが毎日積み重なるとこう見える」という流れで `dashboard.html` に移ると説明しやすい構成です。

## 商談メモ（先方には見せない前提）

- **補助金の話は前面に出さない。** 今年はすでに大口（1,000万円規模）の助成金申請を別ルートで予定しており、今回の話と競合して評点に響くことを気にされている。「お金が返ってくるから」ではなく「実務で使えるか」を軸に話す。人材育成助成金の該当有無は社長も把握していないため、こちらから無理に紐づけない。
- **RPA失敗経験への言及は効く。** 「動かなくなったら終わり」にしない設計思想（ケース2の確認文自動生成、伴走支援ロードマップの「担当者自身が触れるようになる」ゴール設定）を強調する。
- **ゴールはツール納品ではなく内製化。** ロードマップは「担当者が自分で使い倒せる状態になること」を最終ゴールに置いている。ここが刺さるかどうかがクロージングの分かれ目。
- **1年以内での本気の探索フェーズ。** 即決を迫らず、まずは実データでの小さな検証（ロードマップの1〜2ヶ月目）から入る提案が合っている。

## 内容の調整

- フッターの「ご提案者」「連絡先」はプレースホルダーです。送付前に書き換えてください。
- 発注内容・金額例・所要時間はダミーです。実際の単価表や発注書フォーマットがある場合は差し替え可能です。
